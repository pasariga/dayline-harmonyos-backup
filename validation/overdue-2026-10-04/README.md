# 逾期 Deadline 与今日行动验证（2026-10-04）

## 范围与实现

仅处理逾期语义、今日行动及时间经过后的页面刷新。云真实读取/交换继续关闭；数据库仍为 V8，表结构、同步协议、账号、通知策略及身份配置不变。

- 未完成且当前时刻严格超过截止时刻：已逾期。完成项目不参与逾期判断。
- 默认需要处理；可以继续完成、调整截止时间、标记完成或不再追踪。继续/停止决定保存于独立本机 Preferences，绑定 ID 和原截止时刻，不伪装成完成，不加入同步业务字段。改变截止时刻自然失效，未来日期回到正常模型；恢复过期完成项目回到需要处理。
- 未来项目先于继续执行的逾期项目；未处理项目最多占一个处理建议，已有四个可行动项目时不抢占。停止追踪不进入今日行动，完整列表仍保留记录。
- 已逾期单列状态，不当普通高风险，不生成赶在旧日期前的小时计划。无新日期的继续项目可推进任务，但不预测按时完成；任务数量进度仍不换算工时。
- 首页、详情只在可见时安排下一次时间刷新：一般 60 秒，临近截止时提前到截止之后；隐藏时清除，返回前台立即刷新。没有高频轮询或后台调度机制。

## 收尾发现与修复

真实前台跨截止发现：详情标题已经逾期，风险和小时计划仍保留旧缓存。已修复详情缓存读取对响应式时钟的依赖及时间缓存键，并使首页列表风险变化和本地自然日进入渲染键。详情保留草稿返回前台也恢复时钟，不覆盖草稿。

保留失败日志，不把失败准备计为通过：首次夹具编码问题、首页处理建议必须出现的错误断言（四个行动已占满）、输入法首次提示造成后台场景准备超时。后台验证改为无键盘交互的独立未来项目，未接受输入法授权。
