## 先审计，再实施

实施前的七项体验审计和方向见 [DIRECTION.md](DIRECTION.md)，先于生产页面修改建立。旧页面以连续模块呈现推荐、清单、风险、任务、计划，造成多个阅读入口；创建先暴露可选概念；操作反馈与新下一步相隔较远。

本轮方向：**今天是工作台，Deadline 是工作现场。** 打开今天 → 开始当前行动 → 更新任务/进度 → 原业务服务自动重算；情况变化时再校准剩余量。

## 实际变化

- **首页**：今天 / Deadlines 两个本地视图，默认今天；一个首要行动，“开始这一步”进入工作现场，完成任务仍可直接操作。次要行动用行呈现，待处理逾期/冲突与可执行行动分组；不改原推荐排序。完整项目列表不再与今日行动平铺。
- **今日投入**：只读取原全局排期的当天已安排量，称“已安排约…小时”；有未知需求时同时说明待确认，不把安排量当作总需求，也不把没有计划解释为零工作。
- **详情**：名称、截止关系和两个工作面保持上下文；行动先下一步、任务数量进度与任务/手动更新；工作量与计划再看剩余估计、风险和安排。说明、完整排期、资料和备注按需展开。
- **创建**：默认只看名称、截止日期与明确的钟点；今天/明天快捷选择复用日历计算。工时、任务/模式、类型/提醒/备注逐层补充。沿用原校验、事务与草稿保护，无另一套快速写库逻辑。隐藏的非法工时会展开提示，尚未添加的任务输入不会在保存时静默丢弃。
- **完成反馈**：首页下一步与就地撤销、详情固定在工作面下方的回执；深层任务也能找到撤销。没有每次弹窗或庆祝；父任务批量动作及删除确认规则不变。删除没有新增撤销能力。
- **偶尔校准**：行动附近可进入剩余时间确认；编辑时收起重复评估说明，完成后恢复风险/计划。保留沿用上次、修改、暂不确定，不按任务比例推算小时。
- **连续性**：编辑后回到原工作面；切换工作面保留未保存输入并标示未保存，同时把新工作面滚回开头。创建成功只消费一次会话回执。完成/恢复成功后回到当前状态顶部。
- **克制反馈**：160ms 工作面状态转换和下一行动替换淡入；沿用系统导航、日期、时间和确认对话框。没有复杂转场、触感权限、自制 bottom sheet、动画系统或新后台机制。

### 验收发现并修复

1. 深滚动后切换工作面，可能直接看到另一面的末尾：切换时滚回开头，输入仍保留。
2. 深层任务回执离开视口：移到固定工作面栏下，撤销可见。
3. 编辑返回失去工作面：UI 路由携带工作面，业务 ID 和存储模型不变。
4. 仅改名称/截止，行动可能复用旧渲染上下文：渲染键纳入实际显示字段，增加一项回归测试；未改推荐算法。
5. 德文模式按钮实际截断：允许两行和自适应字号，最终包已复验完整显示，见 `last-german-two-line-modes.jpeg`。

### 真实软键盘与旋转边界

- HDC/UiTest点击或输入没有证明键盘实际显示。早期 `runtime-long.log` 的打印文字包含 keyboard，但 `final-keyboard-estimate.jpeg` 没有键盘，**不计键盘显示通过**。
- 直接 IMEKit 探测失败，`native-keyboard-isolated.log` 为0/1，`input method client detached`；失败记录保留，未纳入最终通过数。该环境探测没有留在正式原生测试集里。
- 后续通过 Windows 模拟器窗口直接点按，**真实字母/数字软键盘显示**：名称输入可见；长标题下剩余估计可见，滚动后保存按钮可达，收键盘并取消返回。证据：`final-real-keyboard-create`、`final-real-keyboard-estimate`、`final-real-keyboard-scroll-save` 三组图片/布局。长标题加键盘会压缩视口，需要滚动/收键盘；这不是所有输入法、大字体或尺寸的全覆盖。
- 原生旋转请求的状态保全测试 **2/2**（`native-rotation.log`），但实际显示仍rotation0、1320×2856（`rotation-dimensions.json`），图片也是竖屏。只证明请求后草稿/工作面保全，**不宣称完整横屏通过**。
